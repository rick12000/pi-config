# Create project documentation

Use this procedure only when creating the repository documentation system.

If `.agents/skills/docs/SKILL.md` already exists, use that skill instead.

Exception

If the user explicitly requests changes to the documentation stack, dependencies, environment, renderer, or hosting configuration, run the technical parts of this procedure again. Preserve existing Markdown content unless the user also requested content changes. Rewrite the docs skill afterward.

## Stack

Use only

- Markdown
- MkDocs
- Material for MkDocs
- the project's virtual environment
- Local port `8765`

## Files

Create

```text
docs/
├── index.md
├── getting-started.md
├── requirements.txt
└── architecture/
    └── index.md

mkdocs.yml
.agents/
└── skills/
    └── docs/
        └── SKILL.md
```

Additional architecture Markdown files belong only under `docs/architecture/`.

Do not create other documentation sections.

## Documentation content

`docs/index.md` must contain only

- one short project introduction
- one documentation links section linking to Getting Started and Architecture

`docs/getting-started.md` must contain only the minimum required to install, configure, and run the application and its components.

`docs/architecture/` contains the architecture documentation split into separate Markdown files as required by the application.

`docs/architecture/index.md` links to every architecture document in that folder.

Use relative Markdown links.

## Environment

Set `docs/requirements.txt` to

```text
mkdocs
mkdocs-material
```

Every documentation command runs with the project's virtual environment, never the base Python.

The project's virtual environment is identified by the project's virtual environment usage skill, the `env` instruction generated by `project-venv-setup`.

- If the `env` instruction exists, follow it. Add `mkdocs` and `mkdocs-material` to the project as dev dependencies and update the project's virtual environment to run the documentation tooling.
- If no `env` instruction exists, the project has no virtual environment. Redirect to `project-venv-setup` to create it, then proceed as if the `env` instruction already existed.

Install the dependencies with the project's virtual environment Python from `docs/requirements.txt`.

Add `site/` to `.gitignore`.

## MkDocs

Create `mkdocs.yml`.

```yaml
site_name: <project-name>

theme:
  name: material

markdown_extensions:
  - fenced_code
  - tables
```

Add MkDocs navigation containing

- Home
- Getting Started
- Architecture
- every Markdown file under `docs/architecture/`

## Docs skill

Create `.agents/skills/docs/SKILL.md`.

Its purpose is only to amend, build, or run existing documentation. It must not describe documentation creation.

Use this content structure.

```markdown
---
name: docs
description: Amend, build, or run the existing project documentation.
---

# Documentation

Source directory

`docs/`

Configuration

`mkdocs.yml`

Environment

The project's virtual environment, from the `env` instruction

Dependencies

`docs/requirements.txt`

Serve locally

Use the project's virtual environment Python:

`<project-venv-python> -m mkdocs serve --dev-addr 127.0.0.1:8765`

Open

`http://127.0.0.1:8765/`

Build

Use the project's virtual environment Python:

`<project-venv-python> -m mkdocs build`

When documentation changes, update Markdown under `docs/`, keep `mkdocs.yml` navigation synchronized, then run the production build.
```

## Verification

Run every documentation command with the project's virtual environment Python, never the base Python.

Run the local server on `127.0.0.1:8765`.

Verify the site renders and all internal links resolve.

Run `mkdocs build`.

Do not report success unless both checks succeed.

## Final response

Return only

```text
Documentation setup complete

Browser

<exact serve command>

http://127.0.0.1:8765/

Changed

- <created or materially changed files>
- <documentation changes since the previous version>

Verification

- local documentation site verified
- internal links verified
- production build verified
```
